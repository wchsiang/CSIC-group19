# A：會議建立與內容輸入

這是 Group 19 的 A 功能，已整合到下載的 Repository 工作副本，尚未上傳或合併至 GitHub。現有專案尚無應用程式與既定技術，因此先使用 Python 標準函式庫與 SQLite；技術與共享資料格式仍待團隊審查。

## 執行

需要 Python 3.10 以上，無須安裝套件。在 Repository 根目錄（包含 app.py）開啟 PowerShell：

```powershell
python app.py
```

瀏覽器開啟 http://127.0.0.1:8000 。停止服務按 Ctrl+C。

若連接埠被占用：`python app.py --port 8001`。
資料預設保存在 `data/meetings.sqlite3`；重啟不會清除。可用 `--db 路徑` 指定其他 SQLite 檔案。

## 已實作

- 建立有標題、原始會議文字的紀錄。
- 伺服器檢查空白輸入、120 字標題及 100,000 字內容上限。
- 保存、列出、重新載入及修改既有會議。
- 顯示送出狀態、錯誤與最後儲存時間。
- 切換會議或關閉分頁前提醒尚未儲存的輸入。
- 透過 revision 拒絕舊版本覆蓋新資料，錯誤時保留輸入。
- 匯入 UTF-8 `.txt` 逐字稿（最多 400 KB、100,000 字），覆蓋現有文字前先確認；匯入不會自動儲存。
- 可自行勾選保留瀏覽器草稿。新會議與各筆既有會議各有草稿，重開對應會議即可恢復或清除。
- 開啟已儲存的會議後，可以按「刪除會議紀錄」並確認。若他人已更新該會議，需重新載入後再確認刪除。

目前為本機單一服務，未實作登入、遠端部署、雙人加入、AI 摘要、即時同步、錄音或待辦管理。兩個分頁可以測試讀寫衝突，但不等於已完成 C 的雙人協作功能。SQLite 是本機資料來源，不是跨裝置共用雲端儲存。

## API 與交接

所有寫入均使用 `Content-Type: application/json`。API 沒有啟用跨來源存取；後續前端建議透過同來源服務或開發代理串接。

| 方法 | 路徑 | 功能 |
|---|---|---|
| POST | `/api/meetings` | 建立，回傳 201 與完整紀錄 |
| GET | `/api/meetings` | 回傳 `{ "meetings": [...] }`，列表不含 transcript |
| GET | `/api/meetings/{id}` | 取得完整紀錄 |
| PUT | `/api/meetings/{id}` | 更新原文，需帶目前 revision，回傳更新紀錄 |
| DELETE | `/api/meetings/{id}` | 永久刪除，送出 `{"revision": 1}`（以畫面上的版本為準），成功回傳 200 與 `{"id": "..."}` |

建立輸入：

```json
{"title":"CP2 分工討論","transcript":"小明：我負責輸入功能，週五完成。"}
```

完整紀錄格式：

```json
{
  "id": "伺服器產生的 UUID",
  "title": "CP2 分工討論",
  "transcript": "小明：我負責輸入功能，週五完成。",
  "revision": 1,
  "created_at": "UTC ISO 8601 時間",
  "updated_at": "UTC ISO 8601 時間"
}
```

更新輸入為 `title`、`transcript`、`revision`。成功後 revision 加一。錯誤格式為 `{"error":"原因"}`；400 為無效欄位、404 為不存在、409 為版本衝突、413 為請求大小不符、415 為媒體類型不符。

- B：依 id 取得 transcript，將 AI 產出另外保存；不要覆蓋原文。建議記錄來源 revision，以便原文修改後識別過期摘要。
- C：可以使用讀取 API；共同編輯整理結果、成員確認及權限需另外實作。若編輯原文，需處理 409。
- D：可使用會議列表與詳情 API，待辦資料由 B／C 的產出延伸。

此模組只擁有原文欄位，summary、decisions、actionItems、confirmations 的資料結構仍需全隊確認。

## 驗證

```powershell
python -m unittest discover -s tests -v
node --check static/app.js
node --test tests/test_frontend.cjs
```

測試使用暫存資料庫，不會改動實際紀錄。涵蓋建立／讀取／持久保存、更新、過期版本衝突、無效欄位、不存在紀錄、跨來源寫入與介面資源回應。

人工驗收：

1. 儲存一份中文、多行會議文字，確認顯示成功及列表項目。
2. 重新整理頁面，從列表開啟會議，確認原文保留。
3. 修改並儲存，停止再啟動服務，確認修改仍存在。
4. 使用兩個分頁載入同一份紀錄；第一頁儲存後，第二頁儲存應提示衝突並保留輸入。
5. 尚未儲存時切換會議，確認可取消離開；儲存失敗時內容不消失。
6. 窄視窗與鍵盤操作檢查欄位、按鈕與狀態提示。
7. 匯入 UTF-8 `.txt`，確認中文、多行內容正確；取消覆蓋、無效編碼或過長檔案不改動原文。
8. 勾選保留草稿，輸入後重整並恢復；取消勾選後重整，確認不再提供草稿。

前端自動測試需要 Node.js，僅執行產品不需要。測試使用模擬 DOM，不能代替瀏覽器版面、原生檔案選擇器及關閉分頁提示的人工驗收。
